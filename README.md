# Команда прославления

Веб-приложение для команды прославления: песни с аккордами и транспонированием, расписание служений, режим служения, состав и доступность, голосование за новые песни, уроки, задачи, распевки.

Всё работает бесплатно:

- **GitHub Pages** — хостинг (сайт по адресу `https://danikchervinskiy.github.io/worship/`).
- **Firebase** — база данных, вход по почте, push-уведомления.
- **GitHub Actions** — напоминания о служениях и ночная резервная копия.

Пока в `firebase-config.js` нет настроек, приложение работает в демо-режиме с примером данных. Так можно сначала просто посмотреть, как оно выглядит.

---

## Шаг 1. Firebase: проект и база

1. Откройте [console.firebase.google.com](https://console.firebase.google.com) → **Create a project**. Название любое, например `worship-team`. Google Analytics можно выключить.
2. **Build → Authentication → Get started** → вкладка **Sign-in method** → включите **Email/Password**.
3. **Build → Firestore Database → Create database** → регион `europe-central2 (Warsaw)` → режим **Production**.
4. Там же откройте вкладку **Rules**, удалите всё и вставьте содержимое файла `firestore.rules` из этого архива → **Publish**.
5. На главной странице проекта нажмите иконку **`</>`** (добавить Web app), введите любое имя. Скопируйте объект `firebaseConfig`.
6. Откройте файл `firebase-config.js` и замените `null` на скопированный объект:

   ```js
   self.FIREBASE_CONFIG = {
     apiKey: "…",
     authDomain: "…",
     projectId: "…",
     storageBucket: "…",
     messagingSenderId: "…",
     appId: "…"
   };
   ```

   Эти ключи не секретные — данные защищают правила из пункта 4.

## Шаг 2. GitHub: загрузить приложение

1. На [github.com](https://github.com) создайте репозиторий **`worship`**, тип **Public**.
2. На странице репозитория: **Add file → Upload files**. Перетащите **всё содержимое** распакованной папки, включая папку `.github`.
   - На Mac папки с точкой скрыты. Покажите их сочетанием **Cmd + Shift + .** в Finder.
   - Если папка `.github` не загрузилась, создайте файлы вручную: **Add file → Create new file**, в названии напишите `.github/workflows/notify.yml` и вставьте содержимое. Так же с `backup.yml`.
3. Нажмите **Commit changes**.
4. **Settings → Pages** → Source: **Deploy from a branch** → Branch: **main**, папка **/ (root)** → **Save**. Через 1–2 минуты сайт откроется по адресу `https://danikchervinskiy.github.io/worship/`.
5. Вернитесь в Firebase: **Authentication → Settings → Authorized domains → Add domain** → `danikchervinskiy.github.io`. Без этого вход не сработает.

## Шаг 3. Первый вход

1. Откройте сайт, нажмите **Регистрация**, введите имя, почту и пароль.
2. Появится кнопка **«Стать лидером»** — нажмите. Теперь вы лидер: ведёте песни, расписание и состав.
3. Зайдите в **Ещё → Команда**, добавьте служителей и их роли. В **Профиле** выберите себя в списке.
4. Отправьте команде ссылку на сайт. Каждый регистрируется сам, а вы видите заявку в **Команде** и подтверждаете её, выбирая, кто это в списке служителей.

Песни можно внести вручную или нажать **«Заполнить примером»** на главной, чтобы посмотреть, как всё работает. Пример удаляется одной кнопкой в профиле.

## Шаг 4. Push-уведомления и напоминания

1. Firebase: **⚙ Project settings → Cloud Messaging → Web Push certificates → Generate key pair**. Скопируйте ключ и вставьте в `firebase-config.js`:

   ```js
   self.FIREBASE_VAPID_KEY = 'ВАШ_КЛЮЧ';
   ```

   Сохраните файл на GitHub (откройте его → карандаш ✏ → вставьте → **Commit changes**).
2. Firebase: **⚙ Project settings → Service accounts → Generate new private key**. Скачается JSON-файл. **Это секретный ключ — никому не отправляйте и не загружайте в репозиторий.**
3. GitHub, репозиторий `worship`: **Settings → Secrets and variables → Actions**:
   - вкладка **Secrets → New repository secret**: имя `FIREBASE_SERVICE_ACCOUNT`, значение — всё содержимое JSON-файла;
   - вкладка **Variables → New repository variable**: имя `APP_URL`, значение `https://danikchervinskiy.github.io/worship/`.
4. Вкладка **Actions**: если GitHub спросит, разрешите запуск. Откройте **Уведомления → Run workflow**, чтобы проверить. Дальше он запускается сам каждые 15 минут.
5. Каждый участник включает уведомления в **Профиле**. На iPhone сначала нужно добавить сайт на главный экран (Safari → «Поделиться» → «На экран „Домой“») и открыть приложение с иконки.

Что приходит:

- объявления из ленты (кнопка «Объявить состав», «Напомнить составу», сообщение команде);
- «Вы добавлены в служение» и «Вас сняли со служения» при перестановках;
- напоминание о служении — накануне вечером, о репетиции — за 3 часа.

GitHub запускает расписание с задержкой до 10–15 минут, поэтому уведомления приходят не мгновенно.

## Шаг 5. Ночная резервная копия

1. Создайте второй репозиторий **`worship-backup`**, тип **Private**, отметьте **Add a README file**.
2. **Аватар → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**:
   - Repository access: **Only select repositories** → `worship-backup`;
   - Permissions → Repository permissions → **Contents: Read and write**;
   - срок действия — максимальный (через год токен нужно будет обновить).
3. В репозитории `worship`: **Settings → Secrets and variables → Actions**:
   - секрет `BACKUP_TOKEN` — созданный токен;
   - переменная `BACKUP_REPO` — `DanikChervinskiy/worship-backup`.
4. **Actions → Резервная копия → Run workflow** для проверки. Дальше копия сохраняется каждую ночь, каждая — отдельной версией в истории `worship-backup`.

Восстановить: скачайте `backup/all.json` из `worship-backup` (или нужную старую версию из истории) и загрузите его в **Профиль → Резервная копия → Восстановить**.

## Версии и откат

Каждое изменение файлов на GitHub сохраняется как версия (коммит). Удобнее всего управлять версиями через бесплатное приложение [GitHub Desktop](https://desktop.github.com): история изменений, а у любого изменения — кнопка **Revert changes in commit**, которая возвращает всё как было. Сайт обновится сам через минуту.

Стабильные версии можно отмечать метками: **Releases → Create a new release** → например `v1.0`.

Если меняете файлы приложения, увеличьте `VERSION` в `sw.js` (например `v1` → `v2`), чтобы телефоны быстрее получили обновление.

## Как устроено

```
index.html              страница приложения
firebase-config.js      настройки Firebase (не секретные)
firestore.rules         правила доступа к базе (вставляются в Firebase)
manifest.webmanifest    иконка и название для главного экрана
sw.js                   офлайн-режим и push
css/app.css             стили
js/
  main.js               навигация, нижнее меню, кнопка «+»
  store.js              данные: Firebase, кэш на устройстве, демо-режим
  model.js              роли, выборки, уведомления
  chords.js             разбор аккордов, транспонирование
  dates.js, ui.js       даты, элементы интерфейса
  demo.js               пример данных
  projector.js          тексты для проектора
  views/                экраны: home, schedule, songs, perform, team, suggestions,
                        study, tasks, warmups, feedback, profile, auth, more
scripts/
  notify.mjs            рассылка push и напоминаний (GitHub Actions)
  backup.mjs            резервная копия базы (GitHub Actions)
.github/workflows/      расписание запусков
```

**Кто что может:**

- лидер — песни, расписание, состав, команда, уроки, задачи, распевки, лента; видит конспекты и отзывы;
- участник — смотрит всё, отмечает доступность, голосует, предлагает песни, отмечает пункты задач, сдаёт конспекты, пишет отзывы;
- без подтверждения лидера данные команды не видны никому.

**Формат песен:** аккорд в квадратных скобках перед слогом — `[G]Слава [C]Тебе`. Части песни — строкой `Куплет 1:` или `# Припев`. Текст с аккордами над строками (как на сайтах с аккордами) переводится в этот формат кнопкой в редакторе песни.

**Без интернета:** песни и расписание хранятся на телефоне и открываются без сети. При следующем входе скачиваются только изменения, поэтому бесплатных лимитов Firebase хватает с большим запасом.
